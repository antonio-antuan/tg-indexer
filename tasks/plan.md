## Conventions for every task

Python 3.12, `uv`, `ruff`, `mypy --strict`, `pytest` against the compose Postgres (`docker compose up -d db`). `make ci` runs lint, types, tests, `actionlint`. Every task ends with `make ci` green and its output pasted in the PR. One branch per task or per two small tasks, PR to `main`, never a direct push (Antony's rule). Secrets only in `.env`; `.env.example` lists every key with a placeholder. Logs never carry message text, phone numbers, codes, keys or tokens (SPEC §5.1).

Config keys introduced in P1 (`tgi/config.py`, read from env with defaults): `DATABASE_URL`, `DATA_DIR`, `TDLIB_DB_KEY`, `TG_API_ID`, `TG_API_HASH`, `BACKFILL_YEARS=3`, `SWEEP_DAYS=7`, `PAGE_DELAY_MS=300`, `ON_DELETE=tombstone`, `WINDOW_GAP_MIN=30`, `WINDOW_MAX_CHARS=1500`, `WINDOW_MAX_MSGS=40`, `EMBED_PROVIDER=fake` (P1 default; P2 flips to `voyage`), `EMBED_MODEL`, `POSTGRES_PASSWORD` (non-default, used by compose and `DATABASE_URL`), `MCP_BIND=127.0.0.1:8765` (loopback default; the Docker-network gateway address is set at registration, SPEC §5.6; never hardcoded, Tinker #598). P2 adds `VOYAGE_API_KEY`, `MCP_TOKEN`.

**P1.T5 — Ingestion: backfill and catch-up with checkpoints.** Outcome: `tgi sync` (advisory lock, `--max-minutes`) processes chats in `last_sync_at` ascending order (set at the end of each chat's turn, completed or cut off), runs catch-up (stop when a page's oldest id ≤ `newest_message_id` or the page is empty; `newest_message_id` advanced only once catch-up completes, never per page; a page that is entirely already stored makes catch-up jump to the lowest stored id above the checkpoint; first run takes one page and hands over to backfill) then interleaved backfill per enabled chat, honours `BACKFILL_YEARS` and `chat.backfill_years` (`chats enable --years N`), upserts messages (text or caption, `has_media`, `server_message_id = message_id >> 20`, skipping ids not divisible by `2^20` with an ids-only log line, not fatal to the chat), updates `oldest/newest_message_id`, `backfill_done`, `last_sync_at`, writes `sync_run` stats; resumes after a crash without duplicates. Files: `tgi/ingest.py`, `tgi/cli.py` (`sync`, `chats list|enable|disable|forget`), `tests/test_ingest.py`. Draws on §5.2, §5.3 steps 1–2, 4. Done: A2 and A4 (flood: fake clock); the A3 deleted-checkpoint and interrupted-catch-up cases (scenario raises after page 1, re-run leaves no gap); the A4 stuck-chat case (chat A needs more pages than one run allows, completes within 6 runs, chat B still progresses, A moves behind B); `chats forget` removes the chat's rows with confirmation; `chats enable` refuses a private/basic-group `chat_id` already enabled under another account (SPEC §4 rules).

**P1.T5a — `tgi sync` exit codes and stale runs (small, after T5; owner-approved #630).** Outcome: `tgi sync` exits 0 for `ok`, `time_limited` and `flood_limited`, 2 on `SyncLocked`, 3 on a run that ends in `error`, nothing else (today `time_limited`/`flood_limited` exit 2 and the lock exits 1); after taking the advisory lock and before inserting its own row, a run marks leftover `running` rows `interrupted` with `finished_at = now()`. No migration (`sync_run.status` is unconstrained `text`). Also (decision #632): migration `migrations/0002_windows_dirty_from.sql` (`ALTER TABLE chat ADD COLUMN windows_dirty_from bigint`) and the marker write `least(coalesce(windows_dirty_from, id), id)` issued before every message upsert in catch-up and backfill. Files: `tgi/cli.py`, `tgi/ingest.py`, `migrations/0002_windows_dirty_from.sql`, `tests/test_ingest.py`, `tests/test_migrate.py`. Draws on SPEC §5.3 step 7, §4 `windows_dirty_from` rule. Done: A4's exit-code and `interrupted` clauses: a test invokes the CLI on a `flood_limited` scenario and asserts exit 0; a test seeds a `running` row, runs `sync`, and finds it `interrupted` with `finished_at` set; a test holds the lock on a second connection and asserts exit 2 and no new row. Independent of T6; may be done on its own branch at any point after T5.

**P1.T6 — Edit/delete sweep.** Outcome: the sweep over `SWEEP_DAYS` updates edited messages, applies `ON_DELETE` (`tombstone` sets `deleted_at`, `purge` deletes) only for chats whose sweep is complete (received a message older than the cutoff, or an empty page the archive agrees with: an empty page that should have covered a stored, non-tombstoned message dated inside the window — any such message for the first page, `message_id` below the cursor for a later page — is not trusted, the sweep deletes nothing and logs the chat id only; SPEC §5.3 step 3 guard) and only for messages dated inside the paged range, un-tombstones reappearing messages, sets `chat.windows_dirty_from` before each edit, tombstone, restore or purge (SPEC §4 rule; no in-memory touched map), the hand-off T7 reads, and `tgi sync --resweep-days N <chat_id>` runs the same sweep deeper by hand. Files: `tgi/ingest.py`, `tgi/cli.py`, `tgi/td_fake.py` (new fault kind `{"empty": true}` at call N returns `[]`; port contract unchanged), `tests/test_sweep.py`. Draws on §5.3 step 3, D-TGI-3, §7 deletion risk. Done: A3 except its window clause (both `ON_DELETE` values parametrised; truncated sweep tombstones nothing; an untrusted empty first page tombstones/purges nothing under both `ON_DELETE` values and the next run deletes normally; a window fully deleted above surviving older messages is tombstoned on one sweep; `--resweep-days 365` tombstones one of the 3 "outside" deletions).

**P1.T7 — Windows.** Outcome: deterministic windows per chat (gap, char and message caps, reply prefix, single over-long message truncated), rebuilt for every chat with `windows_dirty_from` set, from the start of the window containing that id, the marker cleared in the same transaction as the window upserts, upserted on `(chat_id, first_message_id)` so unchanged windows keep `window_id` and embedding, `text_hash` unchanged on identical input, changed windows `stale`, vanished windows deleted, tombstoned messages removed. Files: `tgi/windows.py`, `tests/test_windows.py`. Draws on §5.4, §5.3 step 5, §4 window rule. Done: A5; A3 closed here: after A3's sweep only the affected windows are `stale` and the others keep their `window_id`.

**P1.T8 — Embedding pipeline with `fake`.** Outcome: `Embedder` port (`embed_documents`, `embed_queries`, `model`, `dim`), `fake` provider (deterministic token-hash vectors, 1024 dims), batch worker that embeds `stale` windows in batches of 64, leaves failures `stale`, on a `model` mismatch embeds nothing and ends the run with status `error` (`model_mismatch`), `tgi embed --reindex`. Files: `tgi/embed.py`, `tests/test_embed.py`. Draws on §3 Embeddings, §5.3 step 6. Done: after `tgi sync` on a scenario every window has a `window_embedding` row with `model='fake'`; an injected failure leaves exactly those windows `stale` and the run status is still `ok`.

Files: `tgi/search.py`, `tgi/cli.py`, `tests/test_search.py`, `tests/test_links.py`. Draws on §5.5 steps 1–2, 5; §5.2 tags. Done: A6 (incl. the 40-word `ВНЖ,` message and `TIE` not matching `tiene`), A11 with TDLib-shaped ids; `proposed` tags do not filter; `EXPLAIN` of the trigram leg shows the GIN index.
