## Conventions

As in PLAN P1 (Python 3.12, `uv`, `ruff`, `mypy --strict`, `pytest` against the compose Postgres, `make ci` green pasted in every PR, one branch per task, no direct push, secrets only in `.env`, no message text, queries, keys or tokens in logs). New dependencies are added in the task that needs them, with `uv.lock` committed: `httpx` (T1), `mcp` and `uvicorn` (T3). Config keys added in P2 (`tgi/config.py`, `.env.example`): `VOYAGE_API_KEY`, `OPENAI_API_KEY` (optional), `MCP_TOKEN`; `EMBED_PROVIDER` default flips from `fake` to `voyage` in T7 (tests pin `fake` in `conftest.py`); `EMBED_MODEL` defaults per provider (`voyage-4`, `text-embedding-3-small`; the fake keeps `fake`). No new migration: `window_embedding` is already `vector(1024)` and carries `model` and `dim` (SPEC §4), and `embed.ModelMismatch` already covers both.

What P1 left in place for P2 (read before starting a task): `embed.provider(settings)` is the factory to extend (it raises `ValueError` for anything but `fake`); `embed_stale` embeds in batches of `BATCH = 64`, commits each batch with `stale = false`, leaves a failed batch `stale`, honours `should_stop` (`embed_stopped`) under the sync budget; `search.search(conn, queries, *, mode=...)` raises `NotImplementedError` for `hybrid` and `semantic`, fuses by `RRF_K = 60` across queries over keys `("w", window_id)` / `("m", chat_id, message_id)`, bounds `limit ≤ MAX_LIMIT = 50`, raises `BadRange`, returns `Hit` with `as_dict()` and UTC dates; a negated term (`-word`, `-"phrase"`) is one `NOT tsv @@ (neg_ru || neg_es || neg_en)` clause on both keyword legs, with the documented trade-off that a stem collision in any one language excludes the message. Issue #20 (negated hyphenated compound is split) stays open and is not P2 work unless Tinker assigns it; P2 must not change the documented negation behaviour (A6 stays as tested).

## The three open choices from v0.1 (resolved in DR round 1)

1. **`embedder_unavailable` in hybrid mode too: keep it (accepted by DR).** A silent fall-back to keyword inside `hybrid` would hide a dead key, an expired proxy grant or a Voyage outage from the one person who could fix it, since nobody reads this tool's logs; the agent reads tool errors well and the error text says to retry with `mode="keyword"`. One exception class, no extra result field, no change to `Hit`. Alternative rejected: a `degraded` flag on the result, which changes the §5.6 shape for a rare case.
2. **Drop `local_bge_m3`: accepted by DR.** The `Embedder` port stays; adding the provider later is one class in `tgi/embed.py`. DR's optional editorial note ("port-compatible later") goes into SPEC §3 with the next spec edit, not as its own PR.
3. **Exact rerun, as SPEC §7 specifies (DR-1, Tinker's ruling in #662).** v0.2 proposed `hnsw.iterative_scan`; DR showed it stops at `hnsw.max_scan_tuples` and so still cannot guarantee `limit` rows under a selective filter, and `relaxed_order` can misorder what RRF ranks. The exact rerun is deterministic and costs milliseconds over a filtered subset at this size. No spec change.

## Risks found while planning

- **Streamable HTTP in the `mcp` SDK moves between releases** (session handling, the ASGI mount point). T3 pins the SDK version in `uv.lock` and keeps the token middleware as a plain ASGI wrapper around whatever app the SDK returns, so an SDK upgrade touches one function. The stdio transport is the fallback for debugging either way.
- **`get_thread` on deep reply chains** is a recursive query bounded by `limit`; the `(chat_id, reply_to_message_id)` index exists for it (§4). A chain crossing the sweep window may include tombstoned messages; T3 returns them only with `include_deleted`, consistent with `search`.
- **First real embed run is long** (HNSW insert cost plus Voyage tier limits); not a design problem, since `embed_stale` already commits per batch and stops on budget, but Antony should expect it, hence the T7 manual step.
- **Negation is exact only in keyword mode (DR-4).** The keyword legs exclude messages; a window embedding cannot. Aligning the two would mean either excluding a whole window for one negated member (stricter than keyword) or post-filtering the semantic leg's windows by member messages (a second meaning again). The lean choice is to leave the semantic leg un-negated, embed only the positive text, skip the semantic leg for a negation-only query, and tell the agent that message-level keyword negation is `mode="keyword"`; even there a returned window can contain a different message with the excluded term, since negation filters messages and the result is the window. A `hybrid` search with a negated term can therefore rank a window that contains the negated word; the agent notes say so.
- **Query-time model check (DR-2)** adds one `LIMIT 1` read per semantic or hybrid search. It relies on `window_embedding` being homogeneous, which `embed_stale` and `reindex` guarantee today; if a future writer bypasses `_check_model`, the check can pass wrongly. T2 states that invariant in the `embed.py` docstring.
- **Retry-After cap (DR-3).** A `429` with `Retry-After` above 30 s leaves the batch `stale` instead of waiting; under Voyage's free-tier limits that can mean several runs before every window is embedded. `tgi embed` by hand, outside the sync budget, still gets there, and the T7 manual step says so.
- No material risk in T1, T5, T6: HTTP JSON against a documented API behind an existing port, a scripted client, and a bounded `DELETE` under the existing lock.
